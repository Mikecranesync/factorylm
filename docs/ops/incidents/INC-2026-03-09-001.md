## Root Cause

The brain-ingest HTTP endpoint on the VPS (port 8500) became unreachable.
`curl` exit code 28 = `CURLE_OPERATION_TIMEDOUT`. The workflow had a
`|| echo` fallback but GitHub Actions runs bash with `set -eo pipefail`,
so the `jq | curl` pipe failure propagated despite the `||` catch.

Additionally, `if: env.BRAIN_INGEST_URL != ''` doesn't work for secrets
in GitHub Actions — the condition may silently pass or fail depending on
runner version.

No circuit breaker, health check, or alerting existed. Failure was only
discovered by manual inspection.

## Resolution

1. Rewrote brain-feed.yml: `continue-on-error: true`, fast timeouts, dead letter queue
2. Created ci-watchdog.yml: scheduled health check with auto-issue management
3. Created replay-brain-dlq.sh: dead letter replay once endpoint recovers
4. Applied same fix to FactoryLM_OS repo
