    Architecture Overview¶

    This page provides a high-level overview of the FactoryLM architecture. For detailed information about each layer, see the individual layer documentation pages.

    The Big Picture¶

    FactoryLM's architecture is designed around a simple but powerful principle: intelligence flows downward. Over time, common queries and patterns migrate from expensive cloud AI to fast, free deterministic code.

    Query Routing Decision Tree¶

    Understanding how FactoryLM decides which layer to use helps you optimize your interactions:

    flowchart TD
    Query[User Query] --> KB_Search{Knowledge Base<br/>Confidence > 90%?}

    KB_Search -->|Yes| KB_Response[Layer 0: Instant Response<br/>< 100ms, $0]

    KB_Search -->|No| Workflow_Check{Matching Workflow<br/>Pattern Found?}

    Workflow_Check -->|Yes| Workflow_Response[Layer 0: Execute Workflow<br/>< 1s, $0]

    Workflow_Check -->|No| Simple_Check{Simple Command?<br/>Read tags, basic status}

    Simple_Check -->|Yes| Edge_Response[Layer 1: Edge LLM<br/>0.5-1s, $0]

    Simple_Check -->|No| GPU_Check{GPU Server<br/>Available?}

    GPU_Check -->|Yes| GPU_Response[Layer 2: Local GPU<br/>2-3s, Electricity]

    GPU_Check -->|No| Cloud_Check{Cloud Access<br/>Enabled & Available?}

    Cloud_Check -->|Yes| Cloud_Response[Layer 3: Cloud AI<br/>1-2s, $0.01-0.10]

    Cloud_Check -->|No| Fallback[Fallback: Best Available Layer]

    Component Interaction Flow¶

    Here's how the different components work together to process a typical user query:

    sequenceDiagram
    participant User as User<br/>(WhatsApp)
    participant Router as Message<br/>Router
    participant L0 as Layer 0<br/>Vector DB
    participant L1 as Layer 1<br/>Edge LLM
    participant PLC as PLC<br/>Hardware
    participant KB as Knowledge<br/>Base

    User->>Router: "Motor temperature high - what should I do?"

    Router->>L0: Search knowledge base
    L0->>KB: Query: motor temperature troubleshooting
    KB-->>L0: No exact match found (confidence: 75%)
    L0-->>Router: Below threshold

    Router->>L1: Process with edge LLM
    L1->>PLC: Read current motor temperature
    PLC-->>L1: 85°C (normal: 70°C)

    L1->>KB: Search: motor overheating procedures
    KB-->>L1: Found: Motor maintenance guide

    L1->>L1: Generate response with context
    L1-->>Router: Response with troubleshooting steps

    Router-->>User: "Motor temp is 85°C (15°C over normal). Recommended actions: 1) Check cooling fan 2) Verify oil levels 3) Inspect for blockages"

    Router->>KB: Log interaction for learning
    KB->>KB: Create new workflow pattern

    Performance Characteristics¶

    Understanding the performance characteristics of each layer helps you set expectations and optimize usage:

    Layer Response Time Cost per Query Accuracy Use Cases
    Layer 0 < 100ms $0 95%+ (known patterns) Known procedures, documented solutions
    Layer 1 0.5-1s $0 80-90% Simple commands, basic reasoning
    Layer 2 2-3s Electricity only 90-95% Complex analysis, diagnostics
    Layer 3 1-2s $0.01-0.10 95%+ Novel problems, advanced reasoning

    Data Protection¶

    • Encryption at rest - All stored data encrypted
    • Encryption in transit - TLS 1.3 for all communications
    • Zero trust networking - Every connection verified
    • Read-only principle - No write access to industrial systems
    • Audit logging - Complete audit trail of all actions

    Monitoring and Observability¶

    Built-in monitoring provides visibility into system performance and learning:

    System Metrics¶

    • Query routing statistics - Which layers handle what types of queries
    • Response time distributions - Performance across all layers
    • Cost tracking - LLM usage costs and optimization opportunities
    • Knowledge base growth - Learning progress over time
    • Protocol performance - Industrial communication health

    Learning Analytics¶

    • Pattern recognition - Identifying common query patterns
    • Knowledge gaps - Areas needing more documentation
    • User behavior - How different users interact with the system
    • Accuracy improvements - Tracking response quality over time
