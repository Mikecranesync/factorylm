    Layer 0: Code + Knowledge Base¶

    Layer 0 is the foundation and ultimate goal of FactoryLM. This is where intelligence becomes deterministic code - fast, free, and reliable.

    The Goal Layer

    Layer 0 is where we want everything to end up. Every AI interaction, every successful pattern, every piece of knowledge eventually flows down to become instant, deterministic code.

    Overview¶

    Layer 0 consists of deterministic components that provide instant responses without any AI inference:

    graph TB
    subgraph "Layer 0: Code + Knowledge Base"
        VDB[Vector Database<br/>Semantic Search]
        Plane[Plane<br/>Workflow Engine]
        Wiseflow[Wiseflow<br/>Knowledge Gathering]
        Logic[Logic Gates<br/>Pattern Matching]
        Cache[Response Cache<br/>Known Answers]
    end

    Query[User Query] --> Logic
    Logic --> VDB
    Logic --> Plane
    Logic --> Cache

    VDB --> Response[Instant Response<br/>< 100ms, $0]
    Plane --> Response
    Cache --> Response

    Core Components¶

    Vector Database (Semantic Search)¶

    The vector database stores and searches through all industrial knowledge using semantic similarity:

    What's Stored¶

    Equipment Manuals:
  - Every PLC manual, HMI guide, and device specification
  - Troubleshooting procedures and diagnostic guides
  - Fault code definitions and solutions
  - Maintenance schedules and procedures

Historical Data:
  - Previous successful troubleshooting sessions
  - Technician feedback and corrections
  - Common failure patterns and solutions
  - Best practices and lessons learned

Regulatory Documentation:
  - Safety procedures and protocols
  - Compliance requirements (OSHA, FDA, etc.)
  - Industry standards (ISA, IEC, NEMA)
  - Environmental regulations

    Example Queries¶

    # Semantic search examples
query = "Motor overheating at 85°C"
results = vector_db.search(query, top_k=5)

# Returns relevant documents:
# 1. Motor Cooling System Maintenance (95% match)
# 2. Temperature Sensor Calibration (87% match)  
# 3. Motor Overload Protection Setup (82% match)
# 4. Ambient Temperature Guidelines (78% match)
# 5. Motor Bearing Inspection Procedure (75% match)

    Technology Stack¶

    • Embedding Model: all-MiniLM-L6-v2 (local, no API calls)
    • Vector Store: ChromaDB (embedded, no external dependencies)
    • Document Processing: LangChain document loaders
    • Chunking Strategy: Semantic chunking with overlap

    Plane (Workflow Engine)¶

    Plane orchestrates multi-step workflows captured from successful AI interactions:

    Workflow Examples¶

    Motor_Troubleshooting_Workflow:
  trigger: "motor not starting"
  steps:
    1. read_tag: "Motor_Status_Word"
    2. if fault_bit_set:
         read_tag: "Fault_Code"
         lookup_fault: fault_code_database
         return: fault_solution
    3. if power_ok:
         check: "Start_Button_Status"
         check: "Emergency_Stop_Status"
    4. escalate_to: "maintenance_team"

Temperature_Monitoring_Workflow:
  trigger: "temperature > threshold"
  steps:
    1. read_tag: "Current_Temperature"
    2. read_tag: "Temperature_Setpoint"
    3. calculate: "deviation = current - setpoint"
    4. if deviation > 10:
         alert: "high_temperature"
         suggest: cooling_procedures
    5. log_trend: temperature_history

    Logic Gates (Pattern Matching)¶

    Fast pattern matching for common queries and responses:

    Pattern Examples¶

    # Simple pattern matching (regex + logic)
patterns = {
    r".*motor.*start.*": "motor_startup_procedure",
    r".*temperature.*high.*": "temperature_troubleshooting", 
    r".*fault.*code.*(\d+)": "fault_code_lookup",
    r".*pressure.*low.*": "pressure_system_check",
    r".*alarm.*active.*": "active_alarm_procedure"
}

# Complex pattern matching
def match_query_pattern(query):
    # Normalize query
    normalized = query.lower().strip()

    # Check for exact matches first
    if normalized in known_responses:
        return known_responses[normalized]

    # Pattern matching
    for pattern, handler in patterns.items():
        if re.match(pattern, normalized):
            return execute_handler(handler, query)

    # No match - escalate to Layer 1
    return None

    Troubleshooting Knowledge¶

    Common Fault Patterns¶

    Motor_Faults:
  - Overcurrent: Check motor load, verify connections
  - Undervoltage: Check power supply, measure voltage
  - Overtemperature: Check cooling, verify thermal protection
  - Ground Fault: Check insulation, verify grounding

Communication_Faults:
  - Timeout: Check network cables, verify IP settings
  - Protocol_Error: Check configuration, verify protocols match
  - Authentication: Check security settings, verify credentials
  - Bandwidth: Check network load, optimize communication

Process_Alarms:
  - High_Temperature: Check cooling system, verify sensors
  - Low_Pressure: Check pumps, verify system integrity
  - Flow_Deviation: Check valves, verify control loops
  - Level_Alarm: Check sensors, verify tank conditions

    API Interface¶

    Layer 0 provides programmatic access for applications:

    REST API¶

    # Query the knowledge base
GET /api/v1/layer0/search?q=motor+overheating&limit=5

# Execute a workflow  
POST /api/v1/layer0/workflow/execute
{
  "workflow_id": "motor_troubleshooting",
  "parameters": {"motor_id": "M001", "fault_code": "15"}
}

# Get cached response
GET /api/v1/layer0/cache/motor_status_M001

    Python SDK¶

    from factorylm.layer0 import KnowledgeBase, WorkflowEngine

# Initialize components
kb = KnowledgeBase()
workflows = WorkflowEngine()

# Search knowledge base
results = kb.search("pump won't prime", limit=3)
for result in results:
    print(f"Score: {result.score}, Content: {result.content}")

# Execute workflow
workflow = workflows.get("pump_priming_procedure")
result = workflow.execute(pump_id="P001")

    Best Practices¶

    Knowledge Base Management¶

    1. Regular Updates: Keep equipment manuals current
    2. Quality Control: Verify all added knowledge for accuracy
    3. Metadata Tagging: Proper categorization for better search
    4. Duplicate Detection: Avoid redundant information
    5. Performance Monitoring: Track search quality and speed

    Workflow Development¶

    1. Start Simple: Begin with basic linear workflows
    2. Add Complexity Gradually: Introduce branching and conditions over time
    3. Test Thoroughly: Verify workflows work in all scenarios
    4. Document Well: Clear descriptions and parameters
    5. Version Control: Track all workflow changes

    Performance Optimization¶

    1. Index Optimization: Regular vector database maintenance
    2. Cache Strategy: Intelligent caching of frequent queries
    3. Pattern Tuning: Refine pattern matching rules
    4. Resource Monitoring: Watch memory and CPU usage
    5. Network Optimization: Minimize data transfer for remote queries

    Security Considerations¶

    Layer 0 implements security best practices:

    Data Protection¶

    • Encryption at rest: All knowledge base content encrypted
    • Access control: Role-based access to sensitive information
    • Audit logging: Complete record of all queries and responses
    • Data sanitization: Remove sensitive information before storage

    Network Security¶

    • Local operation: No external network dependencies
    • Firewall rules: Restrict access to management interfaces
    • Certificate validation: Secure communications where needed
    • Intrusion detection: Monitor for unauthorized access attempts
