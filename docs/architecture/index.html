    Architecture Overview¶

    FactoryLM is built on a revolutionary four-layer architecture that intelligently routes requests to optimize for speed, cost, and accuracy. Understanding this architecture is key to getting the most out of your FactoryLM deployment.

    The Core Philosophy: Intelligence Flows Downward¶

    The fundamental principle behind FactoryLM is not to use more AI, but to use less AI over time.

    graph LR
    A[Day 1: Query] --> B[Cloud AI] 
    B --> C[Answer]
    A1[Day 30: Same Query] --> B1[Pattern Recognized]
    B1 --> C1[Workflow Created]
    A2[Day 60: Same Query] --> B2[Code Executes]
    B2 --> C2[Instant Answer]

    style B fill:#f9f,stroke:#333,stroke-width:2px
    style B1 fill:#9f9,stroke:#333,stroke-width:2px
    style B2 fill:#9ff,stroke:#333,stroke-width:2px

    Every trace, every workflow, every observation pushes intelligence DOWN the stack toward Layer 0, where responses are instant and free.

    The Four-Layer Stack¶

    FactoryLM's intelligence is distributed across four distinct layers, each optimized for different types of queries:

    🌐 OPTIONAL — Customer choice`"]

    L2["`**Layer 2: Local GPU Server**

    Request Routing Logic¶

    FactoryLM intelligently routes each request to the most appropriate layer:

    def route_query(query, context):
    # LAYER 0: Knowledge base first (instant, free)
    kb_result = knowledge_base.search(query)
    if kb_result.confidence > 0.9:
        return kb_result

    # LAYER 0: Check for matching workflow
    workflow = plane.match_workflow(query)
    if workflow:
        return workflow.execute()

    # LAYER 1: Edge LLM for simple commands
    if is_simple_command(query):
        return edge_llm.process(query)

    # LAYER 2: Local GPU for medium complexity
    if gpu_server.available:
        return gpu_server.process(query)

    # LAYER 3: Cloud as last resort
    if cloud.available and not air_gapped:
        return cloud.process(query)

    Deployment Flexibility¶

    FactoryLM supports multiple deployment scenarios based on your security, budget, and infrastructure requirements:

    Full Stack (All Layers)¶

    Maximum intelligence with cloud access for novel problems.

    Air-Gapped (No Cloud)¶

    Complete functionality without internet connectivity.

    Budget (No GPU)¶

    Cost-effective deployment for smaller facilities.

    Maximum Security (Pi Only)¶

    Completely isolated operation using only deterministic code.

    Read-Only Safety Principle¶

    A fundamental architectural principle of FactoryLM is the read-only constraint:

    What FactoryLM Does

    • ✅ Read tag values from PLCs and industrial systems
    • ✅ Monitor I/O states in real-time
    • ✅ Record fault codes and maintenance history
    • ✅ Analyze trends and predict issues
    • ✅ Suggest actions based on expert knowledge

    What FactoryLM Never Does

    • ❌ Write to PLCs - Read-only for safety
    • ❌ Change setpoints - Diagnostic tool only
    • ❌ Start/stop equipment - No control functions
    • ❌ Modify programs - Observation only

    This constraint eliminates fear, simplifies IT approval, and removes liability while providing maximum diagnostic value.
